# Receive crash investigation — 2026-09-10

Host: Apple Silicon, Resolve Studio 21.0.3.0007, macOS 27.

Repeated SIGBUS crashes were recorded at 14:03, 14:05, 14:07 and
14:29 in Fusion's layer processing. The initial sRender workaround did not
resolve the incident. Memory exhaustion was not established as the cause.

Two serialization mismatches were corrected using settings generated by the
installed Fusion API and Blackmagic's bundled templates:

- Loader assets require top-level `Clips = { Clip { ... } }` records in saved
  settings. `Clip = Input { Value = filename }` is not that representation.
- Point-valued inputs are serialized as positional pairs, not `Point { X, Y }`.

Verification: the installed Lua Receive command imported the current transfer
(27 nodes, two PNG assets) into a new Fusion timeline clip in the separate
project `FFBridge Receive Test 143825`. The clip contained 28 nodes including
its existing MediaOut. Connecting the output and requesting the standard
Viewer did not crash Resolve; no TOOLB_HasError flags were reported. The
diagnostic project was saved. 250 offline tests passed.

Limits: visual fidelity was not confirmed because screen capture failed.
Direct Output.GetValue() on an earlier diagnostic graph triggered a separate
SIGSEGV in TransformMatrix; this is not used by Receive. Hidden standalone
composition Render() returned false, including for a baseline Background,
so those attempts are not evidence of successful rendering. No broad version
compatibility or definitive native crash root cause is claimed.

The prior compatibility quarantine for shape-renderer polygons/strokes remains.
Do not describe unit-test success as proof of native renderer safety.
