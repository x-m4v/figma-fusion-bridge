# Как устроена публикация на GitHub

Имя репозитория: `figma-fusion-bridge`; название проекта в README — Figma Fusion Bridge.
GitHub показывает `README.md` на главной странице. Ссылка «Русский» ведёт на
`README.ru.md`, а оттуда можно вернуться к английской версии.

## Исходники и готовые установочные пакеты

GitHub-репозиторий содержит исходный код, README, LICENSE и настройки сборки.
После отправки кода автоматически запускается **Actions → Check and build**:

- macOS ARM64: сборка Figma-плагина, проверки Python/Lua/Swift, сборка .app и ZIP;
- Windows x64: проверки Python/Lua/GDI, сборка EXE, проверка HTTP из готового EXE,
  установка в отдельную папку с кириллицей и создание ZIP.

Оба успешных задания предоставляют ZIP и SHA-256 в **Artifacts**. Они не являются
публичным релизом автоматически. Чтобы создать релиз:

1. Дождитесь зелёных проверок обеих систем.
2. Пройдите [ручную проверку](MANUAL_ACCEPTANCE.ru.md) в Figma и Resolve.
3. В **Releases → Draft a new release** выберите тег, например `v0.1.0`.
4. Скачайте Artifacts, распакуйте служебный архив GitHub и прикрепите внутренние
   установочные ZIP вместе с `.sha256`.
5. Пока ручная проверка не завершена, отметьте **Set as a pre-release** и явно
   укажите, какие версии Resolve проверены и какие ограничения остаются.

Windows EXE собирается на Windows, а не перекрёстно на Mac. Для ручной сборки:

```powershell
npm ci
npm run build
python -m pip install -r requirements-build.txt
./scripts/build-windows.ps1
```

Исходники открыты под MIT. Не добавляйте `node_modules`, `.build`, .claude,
`session.json`, `credentials.json`, папки с пользовательскими дизайнами и SDK
производителей. Готовые архивы идут в Releases, а не в историю исходников.

Для распространения без системных предупреждений нужны отдельные процедуры
подписи Windows и Developer ID/нотариализации macOS. Текущие пакеты этого не обещают.
